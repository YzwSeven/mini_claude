## 为什么需要会话文件

此前 `messages = []` 只存在于内存。程序退出，列表消失；再次启动时重新创建空列表，模型看不到过去的聊天。

现在每轮任务成功后把整个列表保存到 JSON 文件。下次传入 `--resume`，程序将 JSON 读回 Python 列表，下一次模型请求携带恢复的历史。

这不是把记忆写进模型内部，而是程序重新提供旧消息。

## session.py：保存和读取

```python
SESSION_FILE = os.path.join(os.getcwd(), ".mini-session.json")
```

`os.getcwd()` 是程序启动时的工作目录，不一定是源文件所在目录。文件路径在模块导入时计算。本教程要求从项目根目录启动，因此通常保存到 `D:\PythonProject\mini-claude\.mini-session.json`。

这一版每个工作目录只有一个会话文件；每次保存都覆盖该文件，还没有多会话选择器。

`save_session(messages)` 使用 `open(..., "w", encoding="utf-8")` 打开文件，再通过 `json.dump()` 写出完整列表。`indent=2` 让内容有两格缩进，方便查看。

原教程还提供 `default` 回调：遇到 SDK 消息对象时优先调用其 `model_dump()`。我们目前的 Responses 历史已经是普通字典，但保留原教程的兼容写法。

保存内容包括用户输入、助手输出、工具调用、工具结果，以及首条用户消息中的项目背景。不能只保存最终回答，否则会丢失模型执行任务所需的历史。

`load_session()` 用 `json.load()` 把 JSON 还原为 Python 对象。文件不存在或读取失败时返回 `None`。保存失败时不抛出错误，沿用原教程的最小实现；因此“聊天成功”并不能保证在磁盘不可写时也保存成功。目前也没有原子写入或完整的数据结构校验。

## main() 的逐步变化

### 1. 接收启动参数

```python
def main(argv=None):
    if argv is None:
        argv = sys.argv[1:]
```

例如运行 `python main.py --resume "我喜欢什么颜色？"`，`sys.argv` 的第一项是脚本名称，`[1:]` 跳过它，剩下 `--resume` 和问题。

允许直接传入 `argv`，便于测试时调用 `main(["--resume", "问题"])`，无需打开另一个终端。

### 2. 取出 --resume

```python
resume = "--resume" in argv
argv = [argument for argument in argv if argument != "--resume"]
```

第一行得到布尔值，判断是否需要恢复。第二行删除控制参数，避免后面把 `--resume` 当成问题发给模型。这是原教程的最小解析方式，不是完整的命令行参数解析器。

### 3. 恢复消息历史

```python
messages = []
if resume:
    saved = load_session()
    if saved:
        messages = saved
```

不传 `--resume` 就开始新对话。传入后，有非空保存结果才恢复；空列表或 `None` 都继续使用空历史。

普通新对话在第一次成功保存后会覆盖原来的单一会话文件。

### 4. 文件读取状态重新开始

```python
read_file_state = {}
```

`messages` 是聊天历史；`read_file_state` 是“文件绝对路径 → 读取时最后修改时间”的记录，供编辑保护使用。

本次只持久化聊天历史，没有保存读取状态。因此用 `--resume` 重启后，要编辑哪个已有文件，就先重新读取哪个文件；程序不会启动时把所有文件都读一遍。

例如：上次读取过 `main.py`，退出后恢复聊天，历史中仍有旧内容，但当前读取状态为空，编辑工具仍要求重新读取。

### 5. 判断单次提问模式

```python
one_shot = " ".join(argv).strip()
```

把移除 `--resume` 后的剩余参数拼成问题。没有文字就进入连续聊天；有文字就执行一个用户任务后退出。

```powershell
python main.py
python main.py "帮我查看 main.py"
python main.py --resume "我刚才让你做了什么？"
```

“单次”指一个用户任务，不是只调用模型一次。任务内部仍可能多次调用模型和工具。

### 6. 选择输入来源

```python
user_input = one_shot if one_shot else input("你：").strip()
```

命令行已提供问题就直接使用，否则等待终端输入。

### 7. 退出与清空

交互模式输入 `exit` 或 `quit` 退出。输入 `/clear` 时执行：

```python
messages = []
read_file_state = {}
save_session(messages)
continue
```

清空内存历史和读取状态，并把空列表保存到磁盘，防止下次恢复旧历史。`continue` 回到外层循环等待下一次输入；`/clear` 不发送给模型。

清空后的首次提问会重新加入项目背景，但背景仍是本次程序启动时生成的那份。修改 `CLAUDE.md` 后需要重启加载。

### 8. 任务成功后保存

已有逻辑先复制消息和读取状态，在副本中执行任务。成功后才接受副本：

```python
else:
    messages = turn_messages
    read_file_state = turn_read_file_state
    save_session(messages)
```

这里的 `else` 属于 `try/except/else`，表示没有异常才执行。网络失败或中断时，不用半截工具历史覆盖已保存的成功历史。

这只回退消息和读取状态，不会撤销工具已经写入磁盘的文件。

### 9. 单次模式退出

```python
if one_shot:
    break
```

单次任务成功或发生已捕获错误后都退出，避免循环重复执行同一个启动参数。交互模式则继续等待新输入。

## 完整执行流程

```text
解析启动参数
  → --resume 时加载历史，否则使用空历史
  → 初始化文件读取状态和项目背景
  → 从命令行或终端取得任务
  → 处理退出、清空等本地命令
  → 在历史副本中运行 Agent 工具循环
  → 成功后接受副本并保存完整历史
  → 单次模式退出，交互模式继续
```
