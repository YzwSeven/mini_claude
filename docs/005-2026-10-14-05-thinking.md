## 原教程出处与目的

原项目 docs/05-streaming.md:407 Extended Thinking；python/mini_claude/agent.py:122 模型识别、:135 输出上限、:358 模式判断、:1633 Anthropic 流式请求；python/mini_claude/__main__.py:30 的 --thinking（help 指出 Anthropic only）。让用户选择是否发送 Anthropic 思考配置。

## 逐步修改与语法

1. main.py：检查 `"--thinking" in argv` 得到 True/False；列表推导式去掉启动选项，避免模型把它当作提问。run_agent 的 thinking=False 表示默认关闭。开启时用 thinking=True 关键字参数一路传递，每次工具循环后的模型请求都保留开关。
2. codex_backend.py：ask_model 与 _ask_model_once 接收开关，重试函数也传递它；仅在 Anthropic 分支转交。Codex/OpenAI 不发送 Anthropic 字段。
3. thinking.py：模型名称 lower() 转小写，any(...) 表示候选中至少一个匹配。按原 Python 排除 Claude 3 系列，识别 Claude opus/sonnet/haiku；opus-4-6/sonnet-4-6 返回本地 adaptive，否则 enabled。未开启或未匹配返回 disabled。名称匹配是教程规则，不能当作实时模型能力证明。
4. 输出预算：opus-4-6 为 64000，sonnet-4-6 与其他 opus-4/sonnet-4/haiku-4 为 32000，其他为 16384。关闭时请求 max_tokens=16384；开启时请求 max_tokens=模型上限，thinking={type:enabled,budget_tokens:上限-1}。
5. api_backends.py：`**thinking_options` 将字典展开成 SDK 关键字参数。原有输出转换只留下 text/tool_use，思考块不写入统一历史。流式事件增加 visible_indices：跳过思考块后重新编号文字和工具，使回调与 main 的输出枚举一致，避免最终回答重复打印。

## 执行流程

python main.py --thinking → main 取出开关 → run_agent → ask_model → 重试包装 → Anthropic 请求构造 → 模型思考及回答 → 仅文字即时显示 → 完整回复转为统一格式 → 执行工具或结束。工具执行后的下一次请求仍开启。

## 直接启动

在已有 Anthropic 后端/密钥/模型配置下运行：`python main.py --thinking`，然后直接问“读取 main.py，解释执行流程”。不带 --thinking 则关闭本节配置。默认 Codex 路径加此开关不会改变 GPT 思考强度，启动时会明确提示仅 Anthropic 生效。

## 原文差异与限制

严格以 Python 为准：必须显式开启；TypeScript 示例存在自动启用及不同预算的描述，不套用。原 Python adaptive 是本地标签，请求仍用 enabled/budget_tokens，而不是改成现代 type=adaptive。复现教程版本，不保证名称规则及预算适用于所有当前服务。

GPT/Codex 使用另一套 reasoning 协议，原已有 low 和加密推理历史保持；不能把“不传 Anthropic thinking”说成“GPT 完全不思考”。OpenAI 官方 reasoning 文档：https://developers.openai.com/api/docs/guides/reasoning 。本节未增加 GPT 强度开关。

原教程过滤思考块的历史行为予以保留；未实现签名块跨轮保留等当前服务可能要求的额外处理，不保证真实 Anthropic 多轮工具调用在该历史策略下兼容，不能把离线验证说成线上跑通。后续流式提前执行和并行工具仍未实现。
