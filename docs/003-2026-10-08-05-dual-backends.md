## 文件修改

| 文件 | 作用 |
| --- | --- |
| `codex_backend.py` | 生成统一提示词，选择后端，再发送请求 |
| `api_backends.py` | 转换历史、工具定义，调用两种官方 SDK，统一返回结果 |
| `requirements.txt` | 记录 OpenAI、Anthropic SDK 依赖 |

SDK 安装在项目 `.venv` 中，不需要重装 Python。默认 Codex 路径仍只使用标准库，API SDK 仅在选择对应后端后导入。

## 选择后端

`MINI_BACKEND` 接受 `codex`、`openai`、`anthropic`，默认是 `codex`。

原教程根据 api_base 判断是否为 OpenAI 接口；这里使用显式选择，是为保留已有 Codex 默认接入，避免机器上其他项目遗留的 API 环境变量改变当前服务。这个配置入口属于本项目适配，不能当成原教程原样实现。

`MINI_MODEL` 用于配置所选服务的模型名称。Codex 默认仍为用户选定的 `gpt-5.5`；选择其他 API 时必须明确提供模型名称，不猜测该账号能访问哪个模型。

### 默认 Codex

```powershell
$env:MINI_BACKEND = "codex"
Remove-Item Env:MINI_MODEL -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe main.py
```

继续使用原有 Codex 登录。这里删除的是当前终端进程的模型覆盖变量。

### OpenAI 兼容接口

```powershell
$env:MINI_BACKEND = "openai"
$env:MINI_MODEL = "填写该服务支持的模型名称"
$env:OPENAI_API_KEY = "填写你自己的API密钥"
# 只有使用兼容服务时才需要指定其 API 根地址，通常包含 /v1。
$env:OPENAI_BASE_URL = "https://你的服务地址/v1"
.\.venv\Scripts\python.exe main.py
```

连接官方服务时可删除当前终端的 `OPENAI_BASE_URL`，让 SDK 使用官方默认地址。不要把 ChatGPT/Codex 登录令牌复制为 API 密钥。

### Anthropic 接口

```powershell
$env:MINI_BACKEND = "anthropic"
$env:MINI_MODEL = "填写该服务支持的Claude模型名称"
$env:ANTHROPIC_API_KEY = "填写你自己的API密钥"
.\.venv\Scripts\python.exe main.py
```

`ANTHROPIC_BASE_URL` 可选，仅在需要自定义服务根地址时设置。

这些命令中的密钥文字都是占位符。代码不会自动加载 `.env`；本版本从进程环境变量读取配置。运行不同后端建议开始新会话，不使用 `--resume`，以免把某个服务专属的推理数据跨协议复用。

## 一次请求的执行流程

```text
main.run_agent()
  → ask_model(messages, on_text)
  → 构造中文系统提示词和当前可见工具
  → 根据 MINI_BACKEND 选择入口
      codex：原来的 Responses 请求
      openai：Chat Completions SDK
      anthropic：Messages SDK
  → 将各自结果转换为统一 output
  → run_agent 保存历史、执行工具
  → 下一次请求前再转换历史
```

统一内部消息格式继续沿用现有 Responses 风格。这样 run_agent 和工具实现无需复制三份。

## OpenAI 历史和工具格式

`to_chat_messages()` 把系统提示词放到 system 消息。助手文字变成 assistant 的 content；工具请求变成 assistant.tool_calls；工具结果变成 role=tool，使用 tool_call_id 对应之前请求。

连续的工具请求合并到同一条助手消息中。工具名称、arguments 和调用编号原样保留。Codex 的加密 reasoning 项无法供另一种协议使用，因此转换时跳过，切换服务建议新建会话。

工具定义从当前平铺结构转换为：

```text
type: function
function:
  name: read_file
  parameters: 原来的参数定义
```

`call_openai()` 使用官方 SDK 的流式迭代。文字到达就调用 on_text(text, 0)，同时积累完整文本。工具参数按调用 index 放入字典，并将 arguments 碎片追加；流结束后检查 finish_reason，只有正常结束或完整工具调用才接受。工具参数必须能够解析为 JSON。

如果达到长度限制、被内容过滤或连接未到正常结束就终止，会作为失败处理，避免执行半截工具请求。

## Anthropic 历史和工具格式

`to_anthropic_messages()` 将工具请求转换为助手 tool_use 内容块，工具结果转换为用户 tool_result 内容块。相邻同角色内容合并，以保留消息交替和多工具结果的结构。

工具定义的 parameters 改名为 input_schema，其内容不变。

`call_anthropic()` 监听 text_delta 并立即通知显示层，输出序号使用内容块 index。SDK 的 get_final_message() 返回完整内容块，程序再将 text 转成统一文字消息，将 tool_use 转成统一 function_call。

工具参数由 SDK 收集，不自行解析中途 JSON 碎片。工具仍由 run_agent 执行，服务端没有读取用户电脑上的文件。

## 错误和资源管理

缺少密钥、模型名称或 SDK 时，显示中文错误。APIError 转换成 RuntimeError，供 main 的既有失败处理接住，不显示 SDK 原始错误正文。使用 with 关闭 SDK 客户端和流。失败后仍沿用之前的历史副本回退逻辑。

模型必须支持所选接口、流式输出和工具调用；“OpenAI 兼容”服务可能只兼容部分字段。本版本沿用原文 max_tokens=16384 和 stream_options，并不承诺所有模型都接受这些参数。
