# 第五章第一步：实时显示模型文字

## 出处和范围

参考原项目 `D:\PythonProject\claude-code-from-scratch\docs\05-streaming.md` 中“我们的实现”，以及 `steps/canonical/py/agent.py` 的 `step >=5` 片段：循环显示文字流，再取得完整消息。

本次只实现实时文字显示，没有增加双后端切换、并行工具或流式提前执行工具。原教程使用 Anthropic SDK 的 `text_stream` 和 `get_final_message()`；现有项目使用 Codex Responses SSE，因此通过 `response.output_text.delta` 回调显示，通过 `response.completed` 返回完整响应。工具语义不变。

## 原来为何不是实时显示

请求虽然已经带有 `stream=True`，网络层也逐行接收 SSE，但会忽略中间文字事件。只有完整响应完成，main.py 才一次性打印结果。

开启网络流式传输，与界面实时显示，是两件需要分别接通的事情。

## 三个文件如何连接

```text
main.py 的 show_text
  → ask_model(messages, on_text=show_text)
  → send_request(payload, on_text=on_text)
  → 收到 response.output_text.delta
  → on_text(text, output_index)
  → main.py 立即打印文字

收到 response.completed
  → 返回完整 output
  → 保存助手历史、执行完整工具请求
  → 本轮成功后保存会话
```

### main.py：提供显示函数

每次模型调用前创建 `streamed_items = set()`，记录本轮哪些输出已经通过流显示。

内部函数 `show_text(text, output_index)` 就是回调：网络层有文字时调用它。

首次收到文字时打印“助手：”，然后用 `print(text, end="", flush=True)` 显示片段。`end=""` 避免每块文字后换行，`flush=True` 要求立即输出。每个片段可能包含多个字，流式并不保证逐字发送。

`output_index` 是 Responses 对输出项分配的序号。我们把它记入集合，使后续能区别“已经实时显示的消息”和“只有最终结果的消息”。

请求外层使用 `try/finally`：只要显示过文字，正常完成、异常或用户中断时都会换行，避免下一条状态文字接在半句后面。

### codex_backend.py：传递回调

`ask_model(messages, on_text=None)` 增加可选参数，并原样传给 `send_request()`。

`None` 表示调用者不要求实时通知。回调是本地 Python 函数，不放入 JSON payload，也不发送给模型。模型配置和认证逻辑没有变化。

### codex_transport.py：识别文字事件

原有 SSE 逐行解析继续使用。解析出事件后，若类型为 `response.output_text.delta`，读取 `delta` 文字和 `output_index`，调用显示回调。

文字片段只用于显示，不单独加入 messages。否则片段和最终消息可能重复保存。

`response.output_item.done` 仍收集完整输出项；`response.completed` 仍返回完整响应。如果最终 output 为空，继续按输出序号使用已经完成的输出项补齐。这是此前真实接口测试发现的必要兼容行为。

工具参数的中间片段不执行，仍等待完整响应后由 Agent 分派。

## 为什么不会把答案打印两次

main.py 遍历最终 output 时，对已有流式文字的输出项跳过打印；没有收到文字片段的消息仍正常显示。

即使同一轮有多条消息，其中一条实时显示、另一条只有最终结果，也会分别处理。历史仍统一保存完整 output，工具调用和结果仍用 call_id 对应。

## 失败时的行为

流式显示后才断线时，用户可能已经看到部分答案。但请求未完整成功，main 的既有失败回退逻辑不会把这部分历史写入会话文件。

屏幕显示不能撤销，历史仍只接受成功完成的一轮。这里没有新增自动重试。

## 如何直接体验

从项目根目录运行：

```powershell

```

询问：“请用几段话介绍 Agent 的工具循环。”观察答案是否逐块出现，结束后是否没有重复全文。

再询问：“读取 main.py，简单说明它的作用。”观察工具调用仍能执行，最终回答仍实时出现。

## 已验证内容

使用模拟 SSE、模拟登录和临时会话文件，离线集成测试通过：

- 回调在完成事件之前触发。
- 文字输出不重复。
- 最终 output 为空时仍恢复完整消息和工具请求。
- 纯工具响应能继续下一轮模型请求，call_id 配对正确。
- 混合流式消息和仅最终消息时补打正确。
- 流中断时换行，并保持之前保存的会话文件不变。

没有读取真实令牌，没有联网请求模型。当前结论是本地协议解析和 Agent 接线通过模拟验证。
