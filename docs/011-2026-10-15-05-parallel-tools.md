# 011：OpenAI Chat 路径按原文分批并行执行工具

## 原教程出处与目的

原项目 docs/05-streaming.md:598“并行工具执行”；实际 Python agent.py:1783 起先解析并检查权限，:1821 起分组，之后 asyncio.gather 执行只读批次。原文文档示例字段 fn_name 与实际源码 fn 不同，分组行为相同。

本次补上官方 OpenAI Chat 路径：完整回复后把连续可并行的只读调用分批，先完成上一批再进入下一批。默认 Codex 路径已有提前任务，继续有任务就取结果，没有才执行，不恢复 010 已删除的写前丢弃/停止调度。

## 涉及文件与逐步解释

1. batch_tools.py 的 prepare_tool_calls：先解析全部调用参数并打印名称；解析错误保留调用编号，作为失败结果返回。这里的 ready 仅表示参数解析成功。
2. group_tool_calls：逐个检查 ready 和固定只读名单。如果当前可并行且上一批可并行，就加入上一批；否则建立新批次。读A、读B、写C、读D、读E → [读A、读B]、[写C]、[读D、读E]。不把不相邻的读取跨过写操作合并。
3. execute_tool_batches：并行批次先全部 submit，再等待全部结果；按原输入顺序配对。单独批次在当前线程执行，结束后才处理下一批。工作线程用独立 mtime 字典，主线程采用结果时合并，避免共享字典并发写入。
4. codex_backend.py：只在官方 Chat 分支返回本地 tool_execution_mode=batch，Agent 据此选择调度方法。它不是模型参数，不加入 messages，网络请求字段不变。Codex 分支不加此标记。
5. main.py：看到 batch 标记就调用批量执行器，拿到（原调用、结果），按 call_id 追加 function_call_output；全部完成后 continue 进入下一轮 GPT。未标记的 Codex 沿用现有 early.take 分支。continue 避免一批工具又被下面的循环执行一次。
6. README 和 docs 索引同步增加本节说明。

## 数据如何流转

GPT 返回完整工具调用 → backend 标为 batch → main 提取 output 中的调用 → prepare 生成带参数的条目 → group 分成批次 → 执行第一批的所有读取 → 主线程收集结果、合并读取状态、按编号写入历史 → 执行第二批写入 → 执行第三批读取 → 下一次请求 GPT。

例子：读取 A/B 后写入 C，再读取 D/E。第一批两个任务可以重叠；等待它们都完成后执行 C；C 完成后第三批才启动。即使 B 比 A 先完成，写入历史仍是 A、B、C、D、E 的顺序，每份结果带原 call_id。

和提前执行区别：Codex 是完整单项事件一到就启动；本节 Chat 是完整响应结束后才分批。不是把两种策略强行套在同一条路径里，也不通过删除读结果实现批次顺序。

## 适配差异与尚未完成内容

原文采用异步 asyncio.gather。本项目网络和工具为同步调用，因此用标准库 ThreadPoolExecutor/Future 保持“同批并发、批次顺序、结果配对”的行为；线程上限为 4，多余任务先排队。无需新依赖，没有变更工具定义或参数。

原文准备阶段包含 permission check，当前项目第六章权限系统尚未实现，本次没有伪造权限结果。ready 不是 allowed，不能声称本项目已有原文完整权限判断。后续权限实现必须先检查允许与否，再让允许的只读工具进入并行批次；被拒绝的调用要带原编号返回拒绝结果。

沿用本项目已有参数异常反馈方式：错误参数切断连续只读批次，并作为工具失败文字交回模型。大结果截断继续由 execute_tool 统一处理；原文后续的大结果持久化、预算和上下文切换等机制不在当前实现中。

异常退出会等待已运行的线程，不能强行停止它们；本轮失败沿用 main 的历史副本处理，文件写入不是可回滚事务。公共 API 和模型格式没有改动，未接入新模型或服务。

## 验证方式和结果

分组检查：[读、读、写、读、读] 生成三批，连续非只读各自单批，错误参数单独反馈。使用线程事件证明第一批两个任务都启动后才结束，写操作不会提前启动，第三批不会越过写入；按原顺序写回，即使完成顺序不同也不串 call_id。

main 集成验证 batch 标记、每个工具只执行一次、结果进入下一次模型请求；真实临时文件验证读后编辑的 mtime 记录与写后读取。重跑 Codex 受控提前执行、GPT 后端和流式回归，确认没有恢复写前丢弃。全部通过：工作区 verify_batch_tools.py 验证线程屏障、批次边界、原序配对、单次执行、参数错误、真实临时文件读改读与后端标记；verify_early_tools.py（包含流式回归）和 verify_gpt_backends.py 通过，git diff --check 通过。不调用真实模型，未提交、未推送。
