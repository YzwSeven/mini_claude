# 004：第五章重试机制

## 原教程出处与目的

docs/05-streaming.md:348 的“重试机制”，Python 对应 python/mini_claude/agent.py:78 的 _is_retryable 与 _with_retry。临时限流、服务过载或特定网络错误时重新发送当前模型请求，避免用户重新输入。

## 文件与逐步解释

- retry.py：_is_retryable 检查 429/503/529，以及 overloaded、ECONNRESET、ETIMEDOUT。ModelRequestError 在清理错误显示内容之前保存状态码和判断结果。with_retry 接收一次请求函数 fn，先执行，失败后判断；不可重试或次数耗尽则抛出；否则等待再调用。
- codex_backend.py：ask_model 是重试入口，原请求逻辑放进 _ask_model_once。lambda 每次重新调用它，使流式文字和工具参数的临时累积重新开始。不会重跑整个 Agent 或已经执行的工具。
- api_backends.py：两种官方 SDK 的 APIError 转换为安全异常时保留重试信息，SDK 自身重试仍为 0，避免两层重试相乘。
- codex_transport.py：将 urllib HTTPError.code 映射为 status_code，网络错误同样包装，不改变原有响应解析和凭据遮盖。

## 执行流程

用户输入 → Agent 调用 ask_model → with_retry 调用一次后端请求 → 成功返回完整 output → Agent 执行工具。失败时：判断错误 → 等待 → 重发当前请求。首次加三次重试最多四次；约 1～2、2～3、4～5 秒等待，指数部分上限 30 秒。

已显示的流式片段无法撤回。重试提示以换行隔开，重新生成的文字可能重复显示；失败片段没有写入历史，没有执行其中工具。仅成功的完整回复进入原 Agent 流程。所有尝试失败时沿用 main 的失败回退。

## 适配差异及未完成内容

原文为异步 asyncio.sleep，当前项目是同步网络调用，因此使用 time.sleep；等待规则相同。Codex 是额外协议适配。严格沿用原文错误筛选，不将所有超时、所有 5xx 或所有断流都擅自纳入重试。状态码信息可保留；没有原文匹配文字的 SDK 连接错误仍不重试。Extended Thinking、流式提前执行工具、并行工具仍待后续原文教学。
